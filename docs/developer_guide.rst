Developer Guide
===============

This guide covers the local workflow for updating code, tests, and generated
documentation.

Development Environment
-----------------------

Use the project Conda environment for local work:

.. code-block:: bash

   conda env create -f environment.yml
   conda activate qcml
   pip install -e .

Run Tests
---------

The main test suite lives in `tests/`:

.. code-block:: bash

   python -m pytest tests/

You can narrow scope during development, for example:

.. code-block:: bash

   python -m pytest tests/test_ap2.py -v

Build Documentation
-------------------

Build the Sphinx docs locally before submitting doc or API changes:

.. code-block:: bash

   python -m sphinx -b html docs docs/_build/html

The HTML output is written to `docs/_build/html`.

Autogenerated API Pages
-----------------------

API reference pages are generated from the `.. autosummary::` directives in
`docs/api.rst`. When public APIs change, rebuild the docs so files in
`docs/autosummary/` stay aligned with the current codebase.

Project Conventions
-------------------

- Keep imports grouped as standard library, third-party, then local modules.
- Prefer NumPy-style docstrings for public functions and classes.
- Add or update tests with behavior changes, especially for model wrappers and
  dataset conversion utilities.
- Use `agent_scratch/` for local experiments that should not enter git history.
